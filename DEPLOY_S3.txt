 3. UPLOAD ORDER
===============================================================================

 Use a single "aws s3 sync". It handles ordering, only uploads changed
 files, and sets Content-Type from the file extension automatically.

 STEP 1 - Dry run. Changes nothing. Review the add/remove list.

   cd C:\Users\czw53\Downloads\projects\nfl-team-compare
   aws s3 sync ui\dist s3://YOUR-BUCKET --delete --dryrun

 STEP 2 - Execute.

   aws s3 sync ui\dist s3://YOUR-BUCKET --delete

 STEP 3 - Invalidate the CloudFront cache. REQUIRED.
          index.html changes on every deploy and is already cached.

   aws cloudfront create-invalidation --distribution-id YOUR-DIST-ID --paths "/*"

 If step 3 fails with AccessDenied, use the AWS Console instead:
   CloudFront -> your distribution -> Invalidations -> Create invalidation
   -> enter  /*  -> Create.
 (The IAM user czw5377 was denied cloudfront:ListDistributions, so it may
 not have invalidation rights either.)


 ---------------------------------------------------------------------------
 ABOUT --delete
 ---------------------------------------------------------------------------

 "aws s3 sync" by default only ADDS and OVERWRITES. It never removes
 anything already in the bucket. "--delete" additionally removes objects in
 the bucket that no longer exist locally.

 It matters here because the site was RESTRUCTURED. The old layout had
 pages at the bucket root; they now live under /2025/ and /2024/.

 WITHOUT --delete, these 87 old files stay live forever, orphaned:
   about.html, contact.html, matchup.html, teams/index.html,
   team/*.html (32), elo/*.html (32), leaderboard/*.html (19)

 They form a complete, self-navigating copy of the OLD 2024-only site.
 Their nav links point at each other, so anyone arriving from an old search
 result can browse the entire stale site and never see the season picker.

 WITH --delete, they are removed and those URLs start returning 403. The
 advertised root URL is unaffected.

 Recommendation: use --delete. Run the dry run first so you see the list.

===============================================================================
 6. EXPECTED QUIRKS - NOT BUGS
===============================================================================

 * A bare directory URL 403s.
     https://.../2025/            -> 403
     https://.../2025/index.html  -> 200
   The distribution uses a REST/OAC S3 origin, which does not resolve
   directory index documents. Only the bucket root gets a default root
   object. This does not affect the site, because every internal link is a
   full explicit .html path. It is also pre-existing - /leaderboard/ already
   behaved this way on the old site.

   To make bare directory URLs work you would need either an S3 static
   website endpoint as the origin, or a CloudFront Function that rewrites
   requests ending in "/" to append "index.html". Neither is required.

 * Old deep URLs 403 after a --delete sync. Expected - those pages moved
   into /2025/ and /2024/.
